## 一、产品定位

**一句话**：在虚拟校园地图上标记自己的情绪，让情绪被看见、被记录、被温柔回应。

**核心思路**：情绪记录类产品最大的问题是「记录成本高、用户坚持不下来」。本模块用三个设计破解：

| 痛点 | 解法 |
|------|------|
| 记录太麻烦 | **点地图上的一栋建筑**就完成一次记录，零跳转 |
| 数据没意义 | 情绪热力让地图**自己长成一张心情天气图** |
| 记录完没反馈 | 低落时收到**满屏温柔话语 + 爱心特效**，形成情感回馈闭环 |

## 四、技术架构

### 4.1 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | HTML5 + CSS3 + 原生 JS (ES6) | **零框架、零构建**，可直接双击运行 |
| 渲染 | Canvas 2D | 地图绘制、粒子特效 |
| 后端 | Node.js + Express | 仅做 AI 代理，无数据库 |
| AI | MIMO `mimo-v2.5` | 日/周总结生成 |
| 存储 | LocalStorage | 全部数据本地持久化 |

### 4.2 为什么不用框架

黑客松场景下，**零构建**带来的收益远大于框架便利：

- 队友拿到就是最终产物，不需要 `npm run build`
- 可以直接双击 `index.html` 在浏览器打开调试
- 部署到 GitHub Pages 只需推送静态文件
- 没有依赖，不会因为 node_modules 出问题

### 4.3 模块通信

各模块是**独立对象**，通过全局引用 + 自定义事件协作：

```js
// 地图 → 情绪面板：用自定义事件解耦
document.dispatchEvent(new CustomEvent('locationSelected', { detail: loc }));

// 情绪面板 → 地图：直接调用刷新
if (typeof CampusMap !== 'undefined') CampusMap.refresh();

// 用 typeof 保护，避免加载顺序问题
```

## 五、核心模块详解

### 5.1 地图渲染引擎（map.js，约 1500 行）

**分层结构**

```
静态层（烘焙到离屏 Canvas，只画一次）
  ├─ 草地 + 浅绿斑块
  ├─ 学子湖（沙岸 + 水面 + 波纹 + 荷叶）
  ├─ 土黄步道（三横三纵）
  ├─ 木质栅栏
  └─ 植被（30 树 + 12 灌木 + 12 花丛）

动态层（每帧重绘）
  └─ 10 个地点（建筑 + 光晕 + 徽章 + 标签）
```

**为什么要烘焙静态层**：悬停动画需要 60fps 重绘，如果每帧都画 30 棵树 × 3 层树冠 + 12 处花丛，绘制调用约 400 次；烘焙后每帧只需 1 次 `drawImage` + 10 次建筑绘制，**降到约 11 次**。

**视图变换**

```js
// 世界坐标 ← 屏幕坐标
screenToWorld(p) {
  return {
    x: (p.x - this.view.x) / this.view.scale,
    y: (p.y - this.view.y) / this.view.scale
  };
}
```

所有交互（点击、悬停、拖拽）都先转成世界坐标再判断，缩放平移后依然准确。

**锚点缩放**

```js
zoomAt(screenX, screenY, factor) {
  const newScale = clamp(this.view.scale * factor, 0.6, 3);
  const k = newScale / this.view.scale;
  this.view.x = screenX - (screenX - this.view.x) * k;
  this.view.y = screenY - (screenY - this.view.y) * k;
  this.view.scale = newScale;
}
```

保证鼠标指向的那个点在缩放前后**位置不变**，符合直觉。

### 5.2 建筑素材系统

**素材来源**：团队提供的 6 张 AI 生成像素风建筑图（1280×1280 JPEG，带绿色背景 + 右下角水印）

**离线预处理**（`prep-map-assets.js`，用 jpeg-js + pngjs）

| 步骤 | 做法 | 关键点 |
|------|------|--------|
| **抠背景** | 从四边洪水填充 | 不是简单"绿色变透明"——那样会把建筑内的绿树灌木一起抠掉。只清除与边缘连通的背景 |
| **去溢色** | 边缘像素压低绿色分量 | JPEG 压缩会在边缘留绿边，`if (g > (r+b)/2 + 12) g = (r+b)/2 + 8` |
| **去水印** | 清空右下角区域 | `x > 74% && y > 90%` 整块透明 |
| **裁剪** | 按非透明像素求包围盒 | 去掉多余留白，让 `imgW` 就是建筑实际宽度 |
| **缩放** | 盒式降采样（按 alpha 加权） | 避免透明边缘产生黑边 |

**为什么离线做**：浏览器里每次加载都抠 6 张 1280×1280 图要几百毫秒。预处理后只需加载 1.2MB 的 PNG。

**渲染**

```js
drawBuilding(ctx, loc, cx, by, size) {
  const sprite = this.buildingSprites[loc.sprite];
  if (sprite) {
    ctx.drawImage(sprite, cx - size.w / 2, by - size.h, size.w, size.h);
    return;
  }
  // 素材没加载完 → 画占位框，避免闪烁
  // 没有素材的 4 个地点 → 走 canvas 手绘分支
}
```

高度按素材原始宽高比自动计算，**不会变形**。

### 5.3 安慰弹幕（comfort.js）

**核心算法：抖动网格铺满**

```js
// 按视口面积反推格子尺寸，保证不同屏幕饱满度一致
const target = isNarrow ? 100 : 195;
const cellArea = (w * h) / target;
const cellH = Math.sqrt(cellArea / aspect);
const cellW = cellH * aspect;

// 每个格子放一个气泡 + 抖动
const jx = (Math.random() - 0.5) * cw * 0.72;
```

**交错顺序用素数取模**：

```js
const order = (i * 7919) % total;
const delay = (order / total) * spread;
```

这让气泡**从四面八方同时长出来**，而不是从角落一路推进去。

**渐显**（无位移、无旋转）：

```js
el.animate([{ opacity: 0 }, { opacity: 1 }],
  { duration: 200, delay, easing: 'ease-out', fill: 'both' });
```

### 5.4 爱心收尾特效（comfort-finale.js）

**心形参数方程**

```js
x = 16 · sin³(t)
y = -(13·cos(t) - 5·cos(2t) - 2·cos(3t) - cos(4t))
```

采样 260 个点用于**逐段描绘**（模仿开场动画的"画出来"手感）。

**垂直居中校正**：这个参数方程**不以原点为中心**（y 范围约 -11.5 到 +17）。所以采样后自动求偏移：

```js
this._heartDY = -(minY + maxY) / 2;
```

**粒子系统（284 个）**

| 粒子 | 数量 | 行为 |
|------|------|------|
| 四角星光 | 150 | 贴边缘铺开、向外漂移、闪烁（0.7–1.2 倍振荡） |
| 小爱心 | 46 | 向上飘浮、左右摇摆 |
| 爆发星光 | 88 | 1.7 秒时一次性炸开，带重力衰减 |

**精灵图缓存**：按颜色缓存 3 种精灵（`dot` / `star` / `heart`），全部用 `drawImage`，不逐帧建路径或渐变。

**光芒预渲染**：20 道锥形渐变只生成一次存成 512×512 精灵，每帧只做一次带旋转的 `drawImage`。

**混合模式分层**：
- 爱心填充/描边 → `source-over`（230 点密集重叠，用叠加会过曝成白块）
- 光芒/光环/粒子 → `lighter`（叠加发光正是想要的）

### 5.5 成就解锁队列

**批量解锁的完整状态机**

```js
enqueueUnlockBatch(defs) {
  const pending = this._unlockQueue.length + (this._unlockPlaying ? 1 : 0);
  const total = pending + defs.length;
  defs.forEach((def, i) => {
    this._unlockQueue.push({ def, seq: pending + i + 1, total });
  });
  this._pumpUnlockQueue();
}
```

**token 守卫**（关键：防止旧定时器误关新卡片）

```js
const token = ++this._unlockToken;
const finish = () => {
  if (finished) return;
  finished = true;
  clearTimeout(autoTimer);
  if (this._unlockToken !== token) return;  // 已被新卡片接管
  ...
};
```

**入场动画用 WAAPI 而非 CSS class 切换**：

```js
stage.animate([...], { duration: 680, easing: '...' });
```

因为 `classList.remove → 强制重排 → classList.add` 这套 CSS 动画重播技巧在部分场景会失效，导致第 2、3 张卡片的文字卡在 `opacity: 0`。WAAPI 每次调用都是全新动画对象，**必定重播**。

## 八、踩过的坑（重要经验）

| # | 问题 | 原因 | 解法 |
|---|------|------|------|
| 1 | 地图完全不显示 | `EmotionRecorder.init()` 调了不存在的 `this.render()`，抛错中断整个初始化链 | 移除该调用 + 给 `EmotionApp.init()` 加 try-catch |
| 2 | 数据清除功能失效 | 只清了 LocalStorage，内存里 `records` 还在，下次保存又写回去 | 清 localStorage **+ 清内存 + 重绘所有视图** |
| 3 | 成就只显示一个 | ①每个耗时 5.3 秒（3 个要 16 秒）②CSS 动画重播失效 ③开场动画 z-index 盖住 | 时长压缩 + 改用 WAAPI + 层级轮询等待 |
| 4 | 悬停放大浮得离谱 | `ctx.translate` 在 `scale` 之后应用，位移被二次缩放（`-3 × scale²`） | 把位移放在 `scale` **之前** |
| 5 | 爱心中心过曝成白块 | 230 个粒子用 `lighter` 叠加 | 爱心改 `source-over`，只有烟花用 `lighter` |
| 6 | 爱心整体偏下 | 参数方程不以原点为中心 | 采样后算 bbox 中点自动校正 |
| 7 | 建筑素材抠图吃掉绿树 | 简单按颜色判断，把建筑内的绿植也抠了 | 改成**从四边洪水填充**，只删连通背景 |
| 8 | 线上更新不生效 | GitHub Pages `Cache-Control: max-age=600` | 所有资源加 `?v=` 版本号缓存穿透 |
| 9 | 手机端图例挡住地图 | 图例绝对定位浮在地图上 | 加 `.map-stage` 包装层，手机端图例改 `position: static` 落到地图下方 |

## 十一、可行性说明（评委问询准备）

**Q：AI 挂了怎么办？**
A：所有 AI 功能都有兜底。`EmotionDiary` 内置 `getFallbackDailySummary()` / `getFallbackWeeklySummary()`，AI 不可用时返回基于数据统计的本地文案，功能不中断。

**Q：数据会丢吗？**
A：数据存在用户浏览器 LocalStorage，关闭浏览器不丢。测试工具有备份/恢复功能。换设备不同步（这是 LocalStorage 的固有限制，如需同步需接后端）。

**Q：为什么不用 React/Vue？**
A：黑客松场景零构建的收益更大——队友拿到即用、可直接双击调试、部署只需推静态文件、无依赖故障风险。

**Q：情绪数据怎么保证隐私？**
A：所有数据**只存在用户自己的浏览器**，不上传任何服务器。后端仅做 AI 请求转发，不落库。

**Q：还能怎么扩展？**
A：接入真实校园地图 API、多人情绪热力（需后端）、情绪预测与干预建议、导出分享卡片、暗色模式、PWA 离线支持。
