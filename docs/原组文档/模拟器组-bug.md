# 🐛 Bug 记录

## 已修复

### 2026-09-10 · MiMo 关闭思考模式参数不生效（严重）
- **现象**：按技术框架文档使用顶层 `enable_thinking: false`，实测模型仍输出 `reasoning_content`；当 `max_tokens` 较小时思考链吃满 token 预算，导致 `content` 为空字符串，前端拿不到任何文本。
- **排查**：用参数对比脚本直连 MiMo API 测试三种写法：顶层 `enable_thinking:false`（仍有思考链）、`thinking:{type:'disabled'}`（✅ 生效）、`reasoning_effort:'none'`（✅ 生效）。
- **修复**：`server.js` 改为传 `thinking: { type: 'disabled' }`（保留 `enable_thinking` 兼容），并同步更新 `technical-framework.md` 中的示例代码。

### 2026-09-10 · ai-service.js 模板字符串语法错误
- **现象**：毕业去向本地兜底文案写成 `${dest。}`（中文句号混入插值表达式），`node --check` 报语法错误。
- **修复**：改为 `${dest}。`。

### 2026-09-10 · 毕业报告兜底分支引用未赋值变量
- **现象**：`startFinalSummary` 的 catch 分支中 `is_match: mbtiTypeEquals(p.self_mbti, 'ENFP')` 里引用了尚未完成赋值的 `mbti` 相关逻辑，可能触发 TDZ 错误。
- **修复**：兜底分支直接写 `is_match: false`。

### 2026-09-10 · "继续"按钮双击会跳过事件节点
- **现象**：结果页"继续 →"被快速双击时 `advanceClock()` 执行两次，直接吃掉一个事件。
- **修复**：`proceedAfterChoice` 增加 400ms 推进锁。

### 2026-09-10 · AI +10 导致 JSON 解析失败（严重，间歇性）
- **现象**：MiMo 会输出 `"study": +10`，JSON 规范不允许数字前带 `+`，`JSON.parse` 抛错 → AI 事件被静默丢弃、退回本地兜底事件池。影响事件生成、自定义判定、性格分析、毕业去向四类调用。
- **修复**：`parseAiJson` 改为两段式——先原样解析；失败则经 `sanitizeJson()` 去掉数字前正号与尾随逗号后重试；仍失败才返回 null。所有 JSON 调用都受益。

### 2026-09-10 · 自定义选项统计缺失
- **现象**：`submitCustom` 未设置 `currentEvent._customChoice`，导致引擎中 `recordChoice()` 无法正确统计自定义行动次数，成就系统 "自由灵魂"（用过 5 次以上）永远无法解锁。
- **修复**：`submitCustom()` 在锁定选项后加一行 `currentEvent._customChoice = true`。

### 2026-09-10 · `loadSavedGame` 缺少 version/metrics/semesterStart 字段兜底
- **现象**：旧存档缺这些字段时会导致引擎报错或行为异常。
- **修复**：引擎新增版本提示与字段补全逻辑，确保旧存档也能正常加载。

### 2026-09-11 · 读取已毕业存档会多生成一个事件
- **现象**：毕业时 `startFinalSummary()` 会先写存档（semester=8），之后点「继续上次存档」走 `enterEvent()`，此时 `isFinished()` 虽为 true 仍会调 AI 生成一个"第 49 个事件"，玩家要多走一步才看到毕业报告。
- **修复**：`enterEvent()` 开头增加毕业判定，命中则直接 `startFinalSummary()`。

### 2026-09-11 · AI 把 scene 写成一句话标题
- **现象**：提示词只写"100-150 字描述"，实测模型会偷懒返回 10 字左右的标题式短句，沉浸感断裂。
- **修复**：事件提示词第 1 条改为强制"完整描写、有画面有细节、禁止写成标题或摘要"，并新增第 6 条约束 `background` 只能填九个英文枚举值、且 scene 必须发生在对应地点。

### 2026-09-11 · 毕业去向文案与属性矛盾（精力 5 却写"精力充沛"）
- **现象**：毕业报告中精力只有 5，AI 生成的去向描述却写"精力充沛"。
- **根因**：两条——(1) 提示词只给了裸数值（"精力 5"），没有告诉模型这代表什么，模型按"毕业生"的刻板印象写；(2) 去向本身也让 AI 自选，属性与文案没有任何强制绑定。
- **修复**：`pickDestination()` 用规则判定去向（含"心态 <40 先休整"等优先级），AI 只围绕判定结果写描述；提示词改用 `statSnapshot()` 输出带档位的属性（"精力 5/100：濒临透支"）并点名禁止相反表述；新增 `findContradiction()` 禁词检测，命中则带警告重试一次，仍矛盾就换成 `buildDestinationFallback()` 本地按档位拼的描述。同一套档位说明也加进了性格分析与毕业结语的提示词。

### 「重新开始」按钮点击后毫无反应（2026-09-11 已修）
- **现象**：游戏内顶栏「🔄 重新开始」点了没反应；「📂 读取」同理。
- **根因**：两处都依赖浏览器原生 `confirm()`。原生弹窗在**内嵌浏览器 / 沙箱 iframe** 中会被静默拦截并直接返回 `false`（用户勾选过「阻止此页面创建更多对话框」时同样如此），于是代码 `if (!confirm(...)) return;` 直接返回，什么都不做——用户看到的就是"死键"。
- **复现方式**：CDP 实测，把 `window.confirm` 打桩成返回 `false` 后点击按钮，屏幕停在 `screen-game` 不动；返回 `true` 时正常切换。
- **修复**：新增页面内确认框 `confirmDialog()`（Promise 形式，支持点遮罩/按 Esc 取消、Enter 确定），全部替换原生 `confirm`；z-index 高于加载遮罩，任何时候都能弹出。
- **附带**：重写为 `hardReset()` 完整重置（停打字动画、清内存对局与待播特殊事件、复位面板与创建表单、MBTI 复位），原先只置 `gameState = null`，表单与预加载队列会残留到下一局。引擎新增 `resetGame()` 一并归零 `eventSeq`，避免新旧两局事件 id 撞车。

### 心态 / 人际只涨不跌、长期封顶（2026-09-11 已修）
- **现象**：玩完整局，心态和人际基本都停在 90+，几乎降不下来。
- **实测诊断**：
  - 心态 72% 的事件三个选项全给正分——玩家根本没有"降"的入口。
- **根因**：提示词只写了「学业/人际/心态增长要克制」，从没要求过"下滑要存在"，而模型天然倾向写正向治愈系。
- **修复**：
  1. 提示词加**取舍原则（硬性）**：不允许三个选项在同一维度全为正；必须至少各有一个让心态 / 人际下降的选项；代价优先落在心态/人际/学业，不靠继续扣精力。
  2. 引擎新增 `statPressureHint()`：**属性 ≥70 强制要求提供 -6 以上下滑选项；≤30 强制要求提供 +6 以上回升选项**，形成双向负反馈。
  3. 加强 `balanceDelta` 的消耗侧分段衰减，并硬性要求每事件有 1 个回血选项。
- **效果**：改前 ≥85 占比：学业 100% / 人际 96% / 心态 100%；改后分别降到 14% / 2% / 4%。玩法区分度充足（心态可在 0–100 间拉开）。
