# 整合技术说明 —— 四个模块是怎么并成一个网站的

> 面向：后续要接手维护的同学 / 答辩时被问"你们怎么合并的"时的标准答案
> 对应代码：`最终成品/server.js`、`workbench/`、`shell/`、`tests/smoke-test.js`

---

## 一、合并前是什么状态

四个组各自交了一份**可以独立运行**的完整项目：

| 组 | 目录 | 页面路径 | 后端 |
|----|------|----------|------|
| 主网页 | `主网页/` | `/` | 纯静态，无后端 |
| 模拟器组 | `模拟器组/main/` | `/simulator/` | express + `/api/chat`（支持流式） |
| 模块A 情绪地图 | `模块A/` | `/tools/emotion/` | express + `/api/chat` |
| 模块B 课表排雷 | `模块B/` | `/tools/` | express + `/api/chat` + `/api/fetch-ics`（支持图片） |
| 模块C 日记帮写 | `模块C/` | `/tools/` | express + `/api/chat` |

三处硬冲突，决定了"把四份 server.js 都起起来"这条路走不通：

1. **端口**：四份 `server.js` 全是 `PORT || 3000`，第二个启动就会 `EADDRINUSE`；
2. **路径**：模块B 和模块C 的页面都在 `/tools/`，各自的 `common/` 也都指望挂在 `/tools/` 上，合并会互相覆盖；
3. **接口**：四份 `/api/chat` 逻辑不一致——模块A/C 不支持流式，模拟器的流式是刚需，模块B 还要支持 25MB 的课表截图和多档超时与错误分类。

## 二、合并后的结构：一个服务 + 三条链路

```
                     ┌─────────────────────────────────────────┐
   浏览器  ────────► │  server.js   (Node 原生 http，零依赖)    │
                     ├─────────────────────────────────────────┤
                     │  ① 静态托管（按前缀挂载，见下表）        │
                     │  ② 统一 AI 代理  /api/chat               │
                     │  ③ 入口页外壳注入（左边缘导航条）        │
                     └─────────────────────────────────────────┘
                                  │
        ┌──────────────┬──────────┴──────────┬──────────────┐
   modules/simulator  modules/emotion   modules/schedule  modules/diary
    /simulator/*        /emotion/*        /schedule/*        /diary/*
```

### 链路①：前缀挂载（`MOUNTS` + `mapUrlToRel()`）

URL 前缀在进入磁盘之前被改写一次，四个模块因此各占各的命名空间：

```js
const MOUNTS = [
  { prefix: '/simulator', dir: 'modules/simulator' },
  { prefix: '/emotion',   dir: 'modules/emotion'   },
  { prefix: '/schedule',  dir: 'modules/schedule'  },
  { prefix: '/diary',     dir: 'modules/diary'     },
];
```

`/emotion/common/css/variables.css` → 磁盘 `modules/emotion/common/css/variables.css`。

**这就是"一行模块代码都不用改路径"的原因**：模块内部的 `../common/`、`../../common/` 相对引用，在挂载后依然指向自己那份 `common/`。前端唯一需要知道的绝对地址集中在主网页 `js/config.js` 的 `MODULE_ENTRY` 里。

> 踩过的坑：`mapUrlToRel()` 返回值必须带开头的 `/`。`resolveSafe()` 用 `'.' + relPath` 拼相对路径，少了斜杠会变成 `.modules/...`（一个不存在的目录），表现为**全站四个模块一起静默 404**，但首页照常打开，很容易误判成"模块没拷进来"。冒烟测试里专门锁了这几条 URL 就是为了这个。

### 链路②：统一 AI 代理（`handleChat()`）

不是简单挑一份来用，而是**合并四家的最强实现**：

| 能力 | 来自 | 为什么必须有 |
|------|------|--------------|
| SSE 流式透传 | 模拟器 | 模拟器的"边生成边显示"依赖它，关掉就是转圈 20 秒 |
| 图片识别 + 180s 超时 | 模块B | 课表截图 base64 后请求要跑一分多钟，90s 超时会把它掐死在半路 |
| `finish_reason` / `usage` 回传 | 模块B | 正文被截断时前端才能提示"是 token 用完了"，而不是干巴巴一句"没有内容" |
| `thinking: {type:'disabled'}` | 模拟器 | 实测只写 `enable_thinking:false` 不生效，思考链会吃空 `content` |
| 错误分类成人话 | 模块B | 401/404/429/5xx 分别给可操作建议，而不是统一"AI 连接失败" |
| 30MB 请求体上限 | 模块B | 课表截图 base64 后轻松超过默认限制，会被 body-parser 挡成 413 |

响应体保持成 `{ role, content, finish_reason, usage }`——四个模块的前端都读 `data.content`，因此**前端一行都不用改**。

### 链路③：入口页外壳注入（`ENTRY_PAGES` + `SHELL_TAG`）

合并后用户从主网页跳进某个模块，就"回不去了"（浏览器的返回键不算产品体验）。解决办法是在服务器侧对四个入口 HTML 做一次字符串注入：

```js
const ENTRY_PAGES = new Set([
  'modules/simulator/simulator/index.html',
  'modules/emotion/tools/emotion/index.html',
  'modules/schedule/tools/index.html',
  'modules/diary/tools/index.html',
]);
```

只注入这四个文件（不是全站所有 HTML），注入内容就是 `shell/site-shell.css` + `shell/site-shell.js`：

- 左边缘一条竖排「🏫 双界校园」把手，悬停展开成导航面板（总站 / 工作台 / 四个模块，当前位置高亮）；
- 所有链接 `target="_top"`，即使被 iframe 嵌着也不会把总站塞进框里；
- **被 iframe 嵌入时自动不渲染**（`window.self !== window.top` 直接 return），避免和工作台顶部导航打架；
- 载入 1.2 秒后自动展开 2 秒做一次轻提示，之后交给悬停；`Esc` 收起；尊重 `prefers-reduced-motion`。

这样四个组的源码保持原样，统一外壳由服务器集中管理——将来模块更新，直接覆盖 `modules/` 对应目录即可，外壳不会丢。

## 三、四合一工作台（`/workbench/`）

主网页的定位是"产品门面"（滚动叙事 + 分卡片入口，整页跳转，这是主网页组的定稿），但**演示时整页跳转很费时间**。所以额外加了一个工作台页面，作为"操作台"：

- 顶部标签切换四个模块，`iframe` 承载，切换带时间戳避开缓存；
- 顶栏状态胶囊实时打 `/api/health`：绿=AI 已就绪（显示模型名）、黄=服务在但没配密钥、红=服务不可达；
- ⟳ 刷新 / ⧉ 新窗口 / ⛶ 全屏；
- `#hash` 与地址栏同步，刷新后停在同一个模块；上次使用的模块记在 `localStorage`；
- `Alt + 1/2/3/4` 快速切换；`allow="autoplay"` 让日记帮写的环境音在框内也能播。

两个入口的分工：**主网页负责"讲清楚是什么"，工作台负责"快速摸一遍"**。

## 四、安全与边界

| 项 | 处理 |
|----|------|
| API Key | 只存在于服务端 `.env`，前端全程不接触；代理接口不回传上游错误原文里的敏感信息（截断到 200 字符） |
| 后端源码 | `server.js` / `package.json` / `package-lock.json` / `.env` / `start.*` 一律 403，包括各模块自带的那份 |
| 目录穿越 | `resolveSafe()` 先解码再 `path.posix.normalize`，最后校验结果必须落在站点根目录内；`%2e%2e%2f` 一类编码绕过同样拦住 |
| 点文件 | 任何以 `.` 开头的路径段一律 403（`.env`、`.git`、`.nojekyll` 等） |
| 音频拖动 | 静态服务实现了 `Range` 请求（206），否则长音频无法循环/拖动进度 |

## 五、验证方式

`tests/smoke-test.js` 是这次整合的验收工具，44 项断言分成六组：

1. **总站与工作台**：落地页、样式、`config.js` 的四条入口是否已指向合并后路径、工作台与外壳资源；
2. **四个模块入口页**：逐个拉页面 + 断言关键字 + 断言**外壳脚本确实被注入了**；
3. **各模块关键资源（19 项）**：各自的 `common/`、样式、脚本、图片、音频——一错就白屏或变丑的静默 404 全部覆盖；
4. **安全与健壮性**：源码/密钥 403、目录穿越、404 页、Range、HEAD；
5. **接口**：`/api/health`、ICS 代理参数校验、`/api/chat` 方法校验与空消息；
6. **真实 AI（`--ai` 可选）**：非流式拿 `content` + 流式拿 SSE 分块，两条链路都真跑一次。

命令：

```bash
node server.js
node tests/smoke-test.js        # 44 项
node tests/smoke-test.js --ai   # 追加真实 AI 调用
```

## 六、后续可以怎么接着做

1. **模块换成"插件式"注册**：现在 `MOUNTS` / `MODULE_HOME` / 工作台 `MODULES` / 主网页 `config.js` 四处都要同步，若要长期迭代，可让 `server.js` 读一份 `modules/manifest.json` 自动生成前三处；
2. **把四份残留的 `server.js` 收进 `modules/*/dev-server/`**：现在它们靠拒绝清单挡着，物理隔离更干净；
3. **统一视觉外壳**：目前四个模块各带自己的配色（暖粉 / 渐变紫 / 天气蓝绿），识别度是优点；若要更"像一个产品"，可以在 `shell/site-shell.css` 里再叠一层共通的字体与圆角规范；
4. **进度打通**：日记帮写与情绪地图都在用 `localStorage`，但键前缀不同（`tools_` 等），可以在工作台加一个"今日校园小结"聚合卡片，把两边的数据合起来看。
